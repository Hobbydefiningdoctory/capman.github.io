The Problem

AI agents navigating your app by sight is a fragile architecture

Blind navigation

Your agent clicks through screens, parses visual hierarchy, and infers intent from layout. A button rename, a route change, or a CSS refactor silently breaks the entire flow — with no error, no log, no warning.

Structural Brittleness

Every design iteration is a regression. Agents relying on CSS selectors and DOM traversal cannot distinguish a visual change from a functional one — both cause silent failures in production.

Hallucinated Click Paths

Without a capability map, LLMs invent navigation paths — clicking through five screens to reach a function that could have been a single direct API call with a typed response.

The Technical Edge

Capability matching
Zero UI dependency.

You define a capability manifest — a list of what your app can do and which API handles each thing. At query time, CapmanEngine.ask() runs a three-tier cascade:

  • BM25 keyword match first
  • Fuzzy matching for typos and paraphrases
  • LLM fallback only when confidence is still low

The result is a direct API call, a confidence verdict, and a full execution trace — not a suggested click path.

Without Capman

agent → clicks Home → scrolls → finds button
→ navigates /events → parses DOM table
→ clicks row → reads modal → extracts value
→ breaks on next deploy

With Capman

agent → reads manifest
→ calls getEventAvailability({ id, date })
→ receives typed response → done

FAQ

Common questions

What is a capability manifest?
A capability manifest is a JSON file that describes what your application can do. Each entry — called a capability — names a function your app exposes, specifies the API endpoint that handles it, lists the parameters it accepts, and declares who is allowed to call it (public, user-owned, or admin).
CapmanEngine reads the manifest and uses it to match natural language queries to the right API call. You define the manifest once. Your agent uses it on every query.
Does fuzzy matching work automatically?
Fuzzy matching is opt-in. It's disabled by default. Enable it with fuzzyMatch: true in your engine options. Once enabled, typos and paraphrases that BM25 keyword scoring misses — like "cancle a subscritpion" — are caught by fuzzy matching before the query falls through to the LLM.
Does Capman add runtime overhead?
No. Capman runs entirely at build time. The generated manifest is a static JSON artifact. There are zero runtime dependencies added to your application. The CapmanEngine that ships with the package is consumed by your agent, not your app — your app's bundle is untouched.
Which LLMs does Capman support?
Any LLM that accepts a string and returns a string. capman's LLM interface is model-agnostic — pass Anthropic Claude, OpenAI GPT-4, or any local model wrapper. The LLM fallback only fires for genuinely ambiguous queries where BM25 keyword scoring falls below your confidence threshold. Most queries resolve without any LLM call at all, keeping your costs low.
